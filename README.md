# عصر مکعب‌ها — Voxel Age

بازی استراتژی داستانی، دنیای باز، سبک ووکسل/پیکسلی: از **عصر حجر (صفر)** شروع می‌کنی و تا **دنیای مدرن** (تانک و بالگرد) پیشرفت می‌کنی.
۵ عصر ← ۵ فصل داستان ← هر عصر ظاهر ساختمان، سرباز و جاده عوض می‌شه. دشمن (غارتگرهای شرق) موج‌موج حمله می‌کنه.

## اجرا
```
pip install -r requirements.txt
python app.py        # http://localhost:10000
```
بدون `MONGO_URI` پیشرفت‌ها موقتی‌ان. دیپلوی Render مثل پروژه‌ی قبلی (`render.yaml` آماده‌ست؛ متغیرها: `BOT_TOKEN`, `MONGO_URI`).
با `BOT_TOKEN` ربات تلگرام و مینی‌اپ خودکار راه می‌افته؛ بدون اون هم در مرورگر با شناسه‌ی مهمان کار می‌کنه.

## ساختار (عمداً ساده)
| فایل | کار |
|---|---|
| `app.py` | کل بک‌اند: ذخیره/بارگذاری پیشرفت، رتبه‌ها، هویت تلگرام (initData)، وب‌هوک ربات |
| `web/index.html` | کل بازی (CSS + رندر three.js + منطق + رابط). داخلش با بنر `۱…۹` بخش‌بندی شده |

وقتی بزرگ شد، هر بخش `index.html` (داده‌ها، دنیا، مدل‌ها، رندر، موجودات، داستان، رابط، شبکه، حلقه) یک فایل می‌شه.

## کجا چی رو عوض کنم؟ (داخل `web/index.html`)
- **عصرها، ساختمان‌ها، سرباز‌ها (قیمت/جان/قدرت)، داستان و هدف‌ها:** بخش ۱ (`ERAS`, `BD`, `UD`, `CH`)
- **شکل زمین و جاده:** بخش ۲ (`genTerrain`) · **ظاهر ساختمان‌ها/سرباز‌ها:** بخش ۳ (`MB`, `HUMS`)
- **افکت انفجار/نور شب‌وروز:** `boom` در بخش ۴، `lighting` در بخش ۶
- **سختی دشمن و موج‌ها:** `launchWave` / `stepEnemy` در بخش ۶
- **اندازه‌ی پیکسل‌ها:** تنظیمات داخل بازی (⚙️) یا `QUAL` در بخش ۴

## کنترل
یک انگشت = جابه‌جایی · دو انگشت = زوم/چرخش · روی کارگر و بعد درخت/سنگ = جمع‌آوری · روی زمین = حرکت · روی دشمن = حمله · پایین صفحه = ساخت · روی قلعه = ارتقای عصر.
دسکتاپ: ماوس چپ انتخاب/فرمان، راست-کشیدن چرخش، چرخ ماوس زوم، WASD حرکت دوربین.

## نکته
امتیاز رتبه‌ها از کلاینت می‌آد (برای مسابقه‌ی جدی باید سمت سرور محاسبه بشه).

## اصول مقیاس‌پذیری (برای وقتی پروژه سنگین‌تر شد)
- **همه‌ی ثابت‌ها در `CFG`** (اندازه‌ی نقشه، حدود زوم، کیفیت، نسخه‌ی سیو). نقشه را بزرگ/کوچک کنی فقط `CFG.N` را عوض کن (مینی‌مپ و بقیه خودکار تنظیم می‌شوند). بعد از تغییر نقشه `CFG.SV` را +۱ کن تا سیو قدیمی خراب‌کار نشود.
- **رنگ زمین یک‌جا:** `PAL` (مینی‌مپ هم از همین می‌خواند). جاده‌ها `ROADC`. زمین عمداً تک‌رنگ و کم‌اشباع است تا ساختمان/سرباز/منبع‌ها خوش‌رنگ دیده شوند.
- **رندر سبک:** هر مدل = یک geometry کش‌شده؛ زمین/درخت/ذرات `InstancedMesh`؛ ذرات و پرتابه‌ها pool ثابت (بدون ساخت شیء در هر فریم)؛ تکان گیاهان در GPU (shader) نه CPU.
- **کنترل‌کننده‌ی خودکار FPS:** اگر فریم افتاد وضوح پایین می‌آید و اگر روان شد برمی‌گردد؛ کیفیت «ریز» سایه‌ی ۲۰۴۸ دارد.
- قدم بعدی وقتی بزرگ‌تر شد: تکه‌تکه‌کردن زمین (chunk) با culling، و جدا کردن بخش‌ها به فایل‌های ماژول.


## 🆕 لایه‌ی قبیله (اتصال به کانال یوتیوب) — نسخه‌ی ۲
| فایل | کار |
|---|---|
| `tribe.py` | بک‌اند قبیله: شهروندها، شهرها، شغل‌ها، رای‌گیری، همگام‌سازی یوتیوب |
| `web/tribe.js` | بازی سمت کاربر: شهروند نام‌دار، خانه، شغل، بازار، پنل 👥، برچسب‌ها |
| `web/admin.html` | پنل ادمین در `/admin` (تأیید/افزودن شهروند، رای‌گیری، تنظیمات) |

**متغیرهای Render:** `ADMIN_KEY` (حتماً)، `YT_API_KEY` + `YT_CHANNEL_ID` (اختیاری)، `OPEN_JOIN=1` (اختیاری)، `CITY_CAP` (پیش‌فرض ۳۰).

**روند بازی:** عضو جدید ← (کامنت `!join` یا ثبت در بازی و تأیید ادمین) ← شهروند با اسم، خانه و شغل ←
شهر پر شد ← ادمین رای‌گیری را باز می‌کند (کامنت `#۱ #۲ …` + رای داخل بازی) ← برنده مدیرعامل **شهر جدید از صفر** می‌شود.

**صادقانه:** یوتیوب فهرست سابسکرایبرها را نمی‌دهد، فقط تعدادشان را (→ «ساکنین بی‌نام») ؛ شهروند نام‌دار از کامنت `!join` یا ثبت دستی می‌آید.
اقتصاد و ساختمان‌ها هنوز برای هر بازیکن جدا ذخیره می‌شود؛ فقط «قبیله» (اهالی، شهرها، رای‌ها) مشترک است.
شهروند جدید = یک کارگر واقعی (حداکثر ۲۸ تا هم‌زمان روی صحنه برای لپ‌تاپ ضعیف)؛ بقیه در فهرست‌اند.
